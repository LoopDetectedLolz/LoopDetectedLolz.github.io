## The QAM banner

`theme/widgets/qam.html` is inlined on the index between the header and the featured post. What it sends is real. `demo/make-pcap.py` (needs the `cryptography` package; run it in the cloud container if the Mac lacks it) builds three flows into `demo/traffic.json`, which the build injects as `data-traffic`: `ping` (one cleartext ICMP echo), `voice` (a Teams call to a phone number through an SBC with media bypass: 15,000 SRTP packets from client port 50010, in Teams' audio range, to the SBC's media port 54056, 20 ms of G.711 mu-law each (payload type 0, 8 kHz clock, +160), five minutes, AES_CM_128_HMAC_SHA1_80 with the session keys derived from an SDES master key by the RFC 3711 KDF and the RFC 3711 4.1.1 counter block, `nfn-teams-voice.pcap`, 4.7 MB; libsrtp decrypts every packet with the SDES key) and `chat` (36 TLS 1.2 records under AES-256-GCM, TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384, with a client and a server write key and a record sequence number per direction, a five-minute troubleshooting thread with timestamps, alternating To DS / From DS, `nfn-teams-chat.pcap`). The audio is one second of a synthetic, speech-shaped tone encoded with the Sun reference G.711 encoder (byte-identical to audioop) and looped; it ships in the JSON as `audio` so every browser rebuilds the same bytes. The JSON carries only the recipe (keys, audio, script, SSRC, seq0, ts0, ports, counts, eight sample frames and sha256 checks); the widget regenerates each Teams frame in the browser with WebCrypto (`genVoice`, `genChat`, prefetched six ahead into `GEN`, sample frames as fallback when WebCrypto is missing or the frame scale outruns generation), and `root._gen(kind, n)` returns a frame's hex so a test can compare it with `check` in traffic.json; the generators capture `TR` at call time because that is what bit us. Demo keys ship in the JSON, and every delivered frame is opened with them (`openDelivered`, `openVoice`, `openChat`): the SRTP tag is checked before the payload is decrypted and decoded (`ulawDec`), each chat record's GCM tag before its text shows, and the panels draw what came out; `root._open(kind, n)` builds frame n and opens it, for tests. The Traffic menu (`setTraffic`) swaps flows; voice advances one packet per frame, chat advances one message per delivered frame and TCP-retransmits (the retransmission timer starts at 200 ms and doubles on each try, message stays) when a frame is dropped after 7 attempts, ping repeats. `appDeliver` / `appDrop` hook `dataDone` / `timeoutDone`; `appRender` fills the `.qam-app` panel above the hex pane: ping terminal lines, or a call tile (loss, delay, jitter, MOS from the G.107 E-model with G.711's G.113 Appendix I values, Ie 0 and Bpl 25.1 with packet loss concealment, so a clean call reads 4.4) plus the decrypted RTP header and a 20 ms waveform (flat dashed line when the packet was lost), or delivery stats plus the chat thread with per-message status. Field colour classes come from field names (`fclsOf`), not positions, because the flows have different layouts. The original ping details: frame 1 of `demo/nfn-ping.pcap`, an ICMP echo request from a client, through its AP, to the gateway (118 bytes, 944 bits: 24 of 802.11 header, LLC/SNAP, IPv4 192.0.2.10 to 192.0.2.1, ICMP, a 54-byte cleartext payload, CRC-32 FCS), plus the 14-byte ACK as frame 2. `demo/make-pcap.py` builds the pcap, `demo/nfn-ping.frame.hex` (the bytes) and `demo/nfn-ping.fields.json` (offset, length, name, description per field); the build injects those two as `data-frame` and `data-fields` on the section, and the pcap is linked from the panel for download. Bits go out least-significant bit first per octet (802.11 clause 9.2.2, Annex G), one symbol per particle; scrambling, FEC, interleaving and the PHY header are deliberately skipped so the bits on screen are the bits in the capture, and the explainer says so. The receiver rebuilds bytes as symbols land into a Wireshark-style hex pane (16 per row, offset column, ASCII column on desktop, field colours: 802.11 teal, LLC/SNAP muted, IPv4 blue-light, ICMP green, payload white, FCS grey, corrupted orange), hover or tap a byte for its field readout, and at the end of every attempt runs a real CRC-32 over the received bytes against the received FCS: that comparison, not the corrupted-symbol count, decides ACK vs retransmit. Emit interval is 7 s divided by the symbol count, clamped 30 to 60 ms, so a frame takes about 7 s at 1x regardless of MCS. To change the demo frame, edit and rerun `make-pcap.py`, then rebuild; keep the payload printable ASCII so the ASCII column reads. Canvas animation: a Yagi on the left (mast, boom, reflector, glowing folded-dipole driven element, four directors) aimed along a drawn main lobe at a front-on constellation on the right; ambient blue specks ride the lobe; each data symbol is a bright particle with a tail that rides the cone as a helix (`pathAt`: base point linear along the axis from the driven element to the constellation centre; radius = symbol amplitude x `coneW(s)`, the lobe half-width, which grows from 5px to R so the orbit widens with the beam; angle = s x TURNS x 2pi + the symbol's phase, so at s=1 the helix seen end-on is exactly the constellation point; a slight x shear of 0.22 gives the loops a 3D slant and ramps to 1 over the last 28 percent so the final turn becomes the circle drawn on the grid face). The receiver is drawn twice: `drawPlane` is the constellation seen nearly edge-on in the side view (a thin plane at `L.cx`, width `L.pw` = 2R x `SH` 0.16, Q up, I as depth; the helix's constant x-shear is the same `SH`, so a symbol lands exactly on its projected point), and `drawInset` is the face-on constellation in a square inset (`L.fx, L.fy, L.Rf, L.IS`; right of the canvas on desktop, stacked below the side view on phones, where the canvas grows to about 530px). `target()` is always face-on geometry and `toSide()` projects it; `land()` decodes whichever cell the point fell in (outer cells extend to the edge) and rebuilds the received bits from the cell's Gray label (802.11 labels position p with gray(p), so `buildSyms` places bits b at invGray(b) and `land()` reads gray(cell); neighbouring cells always differ by one bit), so a corrupted symbol's bits are the cell it actually hit, not a random flip. Hits are clickable in either view (`nearDot`, 10px): a `.qam-hit` readout under the hex pane names the symbol, bits, byte(s) and field, offset from the cell centre and the decode, and the byte cells get `.sel`. The scatter is physical: `lb` holds a link budget (20 dBm, 10 dBi Yagi, 2 dBi client, 7 dB NF, free space for the first metre then exponent 3 or free space on the `qam-model` chip, distance 2 to 60 m on the `qam-dist` slider, default 30 m, up to three draggable walls at `WALLS` dry 3 / cinder 6 / brick 12 dB, tap the x above a wall to remove it); `snrDb()` = received power minus the thermal floor for the current width, `sigmaPx()` turns it into a per-axis Gaussian in constellation units (Es from the level set), interference still adds `noise x Rf x 0.16`; `SNRMIN_HT` / `SNRMIN_AG` are typical minimum-SNR tables used for the readout only, rate adaptation reacts to the real corruptions. The Link budget chip shows the profile strip (`drawProfile`: dBm against distance, wall steps, noise floor, SNR bracket, which MCS holds) and the `qam-lbrow` controls; walls stay in the scene when it is hidden and dim the lobe by their loss. The Hits chip cycles the face-on target through hits, heat map and both: `hc` is an offscreen copy of the inset that accumulates every landing with 'lighter' and decays with 'destination-out' (cheap circles, throttled to one frame per 20 us of channel time at the frame scale); `evmDb()` is the RMS error vector over the last 300 landings; `heatClear()` wipes both whenever the picture they measured changes (heat chip, MCS, standard, streams, width, multipath, band). Multipath is one specular bounce (`bounce()`, midpoint of the wall segment by the image-source method); each symbol is one subcarrier (`subOf`, a prime stride across NSD) and its fade is `gainAt(dM, fr)`: extra path in metres from the bench scale, times that subcarrier's frequency, plus a pi phase flip at the reflection, magnitude 0.6. The echo is a real particle in `fly` (`f.ech`, `f.par`) that rides the reflected polyline with the helix phase flipping at the bounce and arrives later by Le/Ld; the direct particle waits at s=1 until its echo lands, then `land()` runs with the equalised SNR (plus 20log10 g), records the vector sum `vs` drawn in the inset (direct + echo = resultant, upfade/downfade) and `drawResp` plots |H(f)| across the width with a dot per particle in flight (desktop only). Streams: `txOff(st)` stacks extra driven elements on the mast (TX2 up, TX3 down), RX1..RXn sit beside the plane, `emit(L,st)` launches one particle per stream per slot on the same subcarrier in `STC` colours, and `land()` charges 6 dB per stream beyond the channel rank (1 in line of sight, 2 with the reflector), a model, not a matrix solve. Landed dots are stored per cell with a fractional offset and re-projected every frame, and in-flight symbols re-aim on resize, so a window resize or fullscreen toggle mid-frame never strands dots in the beam. Interference is a chip, off by default (`intOn`); with it on, hover or touch on the canvas is interference (orange blob, 48px): particles passing through pick up noise, land in the wrong cell (orange dot), the frame fails, no ACK, ACK timeout, DIFS plus binary-exponential backoff, retry; after two failed attempts the MCS steps down (rate adaptation), after three clean frames it steps back toward the selected MCS; seven attempts drops the frame. Timings: preamble by standard with the 802.11 LTF counts (`nLtf`: 1, 2, 4, 4, 6, 6, 8, 8 for 1 to 8 streams), 13.6 us OFDM symbol, SIFS 16, slot 9, DIFS 34, ACK 28 (24 Mb/s, which is what the frame's Duration of 44 already implied), ACK timeout 50, CW 15 to 1023; airtime counts the 16-bit SERVICE field and the BCC tail bits (`tailBits`, none for ax/be, costed as LDPC). 802.11ac combinations the standard leaves out (`EXCL`, `mcsOk`) are disabled in the MCS menu, shown as not defined in Compare rates, dimmed on the ladder and skipped by rate adaptation. Antenna menu (`ANT` table: omni, down-tilt omni, patch, sector, narrow panel, Yagi; each with gain, half-power beamwidth, front-to-back, a lobe width factor `kw`, a glyph and a `pat(theta)` in the plane of the screen, which is the elevation plane; `patA(th)` applies the aim and feeds the lobe, the dashed pattern, the field map, the photon spray and `rxFracCalc`; `gtx()` is the gain toward the client, `ANT.g + 10log10(patA(0))`, and replaces the old fixed GT in `prx`/`prxAt`). Drag on the antenna (56px, 34 on phones) rotates `aim`, tap without moving resets it; drag on the RX plane moves the client along the bench: `cliT` in layout() places `L.cx` between 40 and 100 percent of the way to `L.cxB`, `setDist()` maps 2 to 60 m log-wise and syncs the distance slider. The profile strip has a fixed 0 to 60 m axis with the client as a dot, and on desktop a small polar plot of the pattern with the client direction marked and the off-peak dB. Room chip (`room`, `ROOM` losses ceiling 6 / floor 7 / wall behind 4 dB, `roomGeom`, `roomPaths` ranks direct and one-bounce paths by net gain = pattern gain toward the surface + antenna gain − reflection − extra path loss, `linkGain()` feeds `gtx()`, `drawRoom`, and `emit` sets `f.via` so `pathAt` routes the particle antenna → surface → plane with a phase flip and a frame blend over the last 20 percent so it still lands on its constellation point). Scene menu (`scene` bench | link): Long link is a separate block (`LL` state, `llModel` with F1 = sqrt(λ d1 d2 / d), earth bulge d1 d2 / 2kR with k = 4/3, knife-edge loss `keLoss(v)`, worst of the obstacles and 39 ground samples, budget PTX + 2·gain − FSPL − diffraction against the same noise floor; `drawLink` with scenery by distance tier, an earth fill that swallows a blocked line, draggable tree/building/hill via `llPointer`, readout with verdict and the vertical exaggeration; `#qam-llrow` has the log distance slider 30 m to 50 km and both mast heights; `stepInner` diverts to `drawLink` and `setCur` to `llPointer` when the scene is link). Controls: Standard (802.11a, n, ac, ax, be; no "Wi-Fi 3" label, the Wi-Fi Alliance never named one; the `STD` table sets symbol time 4 or 13.6 us, data subcarriers per width, allowed widths, MCS list, max streams, preamble by stream count, carrier 5.2 GHz; 802.11a uses its own eight-rate table and the ladder reads RATE), MCS, streams, width, a Time slider (0 to 4, four bands: 0 to 1 frames, real time to 1 ms per screen second, no flight, a DCF cycle stepped in real microseconds with a to-scale strip of the last 1.2 ms and a frames-per-second estimate, symbols land instantly, the cursor in the cone corrupts a share of them; 1 to 2 symbols, today's particle view, 8x down to 0.125x with the label computed from the real airtime; 2 to 3 waves, 1e8.3 to 1e9.3 slow-motion, the symbol scene freezes and a low-resolution field of the carrier renders through an ImageData map shaped by the antenna pattern (every `pat()` is power: the link budget takes 10 log10 of it, the field its square root; the Yagi is a cos^5 main lobe 59 degrees wide, side lobes near 65 degrees about 16 dB down and a back lobe about 20 dB down), with 1/r^0.4 falloff, a mirror-image source below the wall, phase-inverted like the symbol view's echo, when Multipath is on, and the cursor as a second radio on a channel 10 percent higher; 3 to 4 photons, 1e9.3 to 1e10.3, photons sampled from the power pattern travel at c on a 3 m bench with a running count against the real number in one OFDM symbol (3.9 x 10^17 for 13.6 us at 20 dBm), the share of the pattern inside the receiver's aperture, and the odds that any one photon reaches the client, from the path loss and both gains (`photonOdds()`)), pause, Multipath toggle (reflector under the beam; each symbol gets a teal echo on a longer path; fade gain |1 + 0.6 e^(i phi)| from the extra path length at a 34px wavelength; the receiver equalises amplitude so the fade scales landing noise by 1/gain; Streams >= 2 models two RX chains and combines the power of both fades), Compare rates table (rows clickable), click on text for the explainer. Every attempt opens with a preamble (eight white pulses, constellation rotated by a random carrier offset that eases to zero, LOCKED label) before data; symbols corkscrew down the beam as phasors (radius = amplitude, start angle = phase, TURNS=5), trails persist full length and fade from the source once the particle passes 90 percent, then ghost out after landing; "Follow a symbol" tags the next symbol, slows to 0.5x, draws a 3x lens with a phasor mini-plot and a caption (bits, amplitude, phase, then the receiver's verdict), and restores speed. A live MCS ladder sits top-left: bright step = rate in use, outlined = selected, marker eases between steps, flash on rate up/down, eased Mb/s figure. Interference radius 48px (36 on mobile). Rendering has four detail tiers keyed to speed (slower = more detail: trail point spacing 2.2 to 9px, trail cap 260 to 50 points, specks 150 to 40, blur only at the top tiers) plus a governor that drops a tier when the measured draw cost passes 9 ms and recovers below 3.5 ms; trails are stroked one path per half-turn of the corkscrew, landed dots and constellation points are batched paths with no shadows. `root._dbg()` returns drawMs, tier, counts. Fullscreen is a pseudo-fullscreen (fixed, opaque, canvas 56vh, touch-action none so a finger drags interference instead of scrolling; Escape exits); on touch devices the hint says to use it. Pauses when hidden, static under reduced motion. Kit colours only; orange is the interference and warning colour.

**Live**: the simulator's Live chip drives the link from a real client. `client-pull.py` on the laptop reads one wireless client from Central (GET only; snapshot with `--out`, or `--serve 8830` polls and answers `/latest.json` on 127.0.0.1 with CORS open) and the page reads that: `inferPhy` picks the standard, streams and width whose top rate matches the client's maximum, `mcsForRate` the MCS for its current rate, the feed's SNR replaces `prx()` (eased per frame), and `retry_pct` fails clean frames at that rate in `dataDone`. Controls park while a feed drives; `root._mon(reading)` applies one and `root._mon(null)` releases. A reading with a `trail` (from `--trail HOURS`, the client's mobility trail plus each visited AP's radios) shows the journey: an SVG strip of landings coloured by AP with joins hollow, the holding AP as a band, latency ticks and a weak-signal wash, a scrub slider, click to jump and Play; `journeyGo(i)` turns hop i into a reading of its own (`hop: true`, so the PHY is not re-inferred and the SNR picks the MCS) and `root._journey(i)` does it for tests. `lab-kick.py` is the one script that writes to Central: one client's disconnect, guarded by `--yes` and a group check. With `--lan` the relay also answers `/glance`, `/mark?note=`, `/marks` and `/alerts` for a Watch or phone on the Wi-Fi (`WATCH.md` has the Shortcuts); marks come back in `latest.json` and draw as flags on the strip. Monitoring is a minute's average, so the page says it shows the stream statistically, not a replay.
