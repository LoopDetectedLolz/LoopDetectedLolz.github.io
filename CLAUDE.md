# Network Field Notes

Dustin Burns' personal tech blog. Static site, generated by one Python script, deployed to GitHub Pages.

Live at https://networkfieldnotes.com

## Commands

```bash
python3 build-blog.py                              # regenerate the whole site
python3 -m http.server 8787 --bind 127.0.0.1       # local preview (8080 is taken)
git add -A && git commit -m "..." && git pull --rebase origin main && git push origin main
```

Requires `markdown` (`python3 -m pip install --user markdown`) and `rsvg-convert` (Homebrew).
Pages redeploys about a minute after push.

## Layout

| Path | What it is |
|---|---|
| `build-blog.py` | The entire generator. `SITE`, `BASE_URL`, `CUSTOM_DOMAIN` at the top; page template below. |
| `posts/*.md` | One file per post. Front matter plus markdown. The only place post content lives. |
| `theme/style.css`, `theme/app.js` | The design system (liquid glass) and the small client script: header scroll state, rise stagger, zoom/genie transitions, index filter and search. Inlined into every page at build. |
| `graphics/*.svg` | Hand-drawn heroes, one per post, plus `mark.svg`. |
| `logo/`, `character/` | The brand kit: wordmark, mark, favicon, and Rig the mascot in seven poses. Do not redraw these. |
| `index.html`, `about.html`, `socials.html` | GENERATED. Never edit by hand. |
| `p/<slug>.html` | GENERATED. One standalone page per post, its own canonical URL and OG tags. |
| `og/<slug>.png` | GENERATED. 1200x630 social preview cards, rendered from SVG. |
| `sitemap.xml` `rss.xml` `robots.txt` `CNAME` | GENERATED. |
| `audit/`, `evidence/`, `verification-register.md` | Fact-checking trail. Gitignored, stays local. |

Anything marked GENERATED is rewritten on every build. Edit the source, not the output.

## Front matter

```
---
title: Plain title with a hook
slug: kebab-case-matching-filename
date: YYYY-MM-DD
tags: Comma, Separated, Max 4
hero: hero-<name>.svg
summary: One or two sentences. Becomes the card text, meta description, RSS description and social preview.
origin: One line on where it came from
---
```

Optional: `bot: nfn-bot-<pose>.svg` to pick which Rig pose sits on the post page (default is picked from the tags; see `BOTS` in `build-blog.py`).

Read time is calculated from word count. Posts sort by date, newest first, and the newest becomes the featured hero on the index. The featured post also gets a hidden card in the grid so category filters and search still find it.

## Categories and colours

The card pill comes from the first tag via `CAT_MAP` in `build-blog.py` (clearpass -> NAC, wireless -> Wireless, switching -> Switching, process/documentation -> Docs; a survey or Ekahau tag -> RF survey). If `origin` mentions a lab build the category becomes Lab. Colours are fixed: Wireless green, NAC blue, Lab red, everything else neutral glass. The active nav pill is an orange three-quarter ring. Those are the only places red, orange or amber appear on the site.

## Rules that matter

**The repo is public and git history is permanent.** Before every commit, grep the markdown and the built pages for customer names, site names, cities, street addresses, WEI document numbers, AP serials, BSSIDs, client MACs, and internal profile or SSID names. Posts describe real engagements; the customer is never identifiable.

**No em dashes, en dashes, or spaced-hyphen substitutes.** `grep -n -E "—|–| - " posts/*.md` must be empty before building. Rewrite the sentence rather than swapping punctuation.

**Configs are placeholders.** `<CONTROLLER-IP>`, `<VRF-NAME>`, RFC 5737 ranges for IP examples. Never a real running-config line.

**Claims get verified against vendor documentation before publishing.** Release notes, CLI references, user guides, datasheets. Forum posts are leads, not citations. A prior audit of 234 claims across seven posts found 15 wrong and 50 overstated, so this is not optional. The per-post table goes in `audit/<slug>.md`, the roll-up in `verification-register.md`.

**Date-stamp claims about what a product can't do.** Name the version and when it was measured, so the statement stays true after the vendor ships a fix.

**No contact or invitation copy in posts.** No "get in touch", "reach out", "send it my way", "corrections welcome", "I'd like to hear about it" or anything that asks the reader to contact Dustin. Not in the bottom line, not in the post-end card, not in the About page. Posts end on the takeaway.

**Write SVGs with a shell heredoc, not a file-writing tool**, then check the byte count. File tools have silently written a few bytes of binary instead of the content. Always render and look at a hero before building: `rsvg-convert -w 900 -h 340 graphics/hero-x.svg -o /tmp/x.png`.

## The QAM banner

`theme/widgets/qam.html` is inlined on the index between the header and the featured post. What it sends is real. `demo/make-pcap.py` (needs the `cryptography` package; run it in the cloud container if the Mac lacks it) builds three flows into `demo/traffic.json`, which the build injects as `data-traffic`: `ping` (one cleartext ICMP echo), `voice` (15,000 SRTP packets, 20 ms each, five minutes, AES-128-CTR + HMAC-SHA1-80, `nfn-teams-voice.pcap`, 3.2 MB) and `chat` (36 TLS 1.2 AES-128-GCM records, a five-minute troubleshooting thread with timestamps, alternating To DS / From DS, `nfn-teams-chat.pcap`). The JSON carries only the recipe (keys, script, SSRC, seq0, ts0, counts, eight sample frames and sha256 checks); the widget regenerates each Teams frame in the browser with WebCrypto (`genVoice`, `genChat`, prefetched six ahead into `GEN`, sample frames as fallback when WebCrypto is missing or the frame scale outruns generation), and `root._gen(kind, n)` returns a frame's hex so a test can compare it with `check` in traffic.json; the generators capture `TR` at call time because that is what bit us. Demo keys ship in the JSON so the decrypted view is honest. The Traffic menu (`setTraffic`) swaps flows; voice advances one packet per frame, chat advances one message per delivered frame and TCP-retransmits (200 ms added, message stays) when a frame is dropped after 7 attempts, ping repeats. `appDeliver` / `appDrop` hook `dataDone` / `timeoutDone`; `appRender` fills the `.qam-app` panel above the hex pane: ping terminal lines, or a call tile (loss, delay, jitter, MOS from a G.107-style E-model with Ie 10 and Bpl 20) plus the decrypted RTP header and a 20 ms waveform (flat dashed line when the packet was lost), or delivery stats plus the chat thread with per-message status. Field colour classes come from field names (`fclsOf`), not positions, because the flows have different layouts. The original ping details: frame 1 of `demo/nfn-ping.pcap`, an ICMP echo request from a client to its AP (118 bytes, 944 bits: 24 of 802.11 header, LLC/SNAP, IPv4 192.0.2.10 to 192.0.2.1, ICMP, a 54-byte cleartext payload, CRC-32 FCS), plus the 14-byte ACK as frame 2. `demo/make-pcap.py` builds the pcap, `demo/nfn-ping.frame.hex` (the bytes) and `demo/nfn-ping.fields.json` (offset, length, name, description per field); the build injects those two as `data-frame` and `data-fields` on the section, and the pcap is linked from the panel for download. Bits go out least-significant bit first per octet (802.11 clause 9.2.2, Annex G), one symbol per particle; scrambling, FEC, interleaving and the PHY header are deliberately skipped so the bits on screen are the bits in the capture, and the explainer says so. The receiver rebuilds bytes as symbols land into a Wireshark-style hex pane (16 per row, offset column, ASCII column on desktop, field colours: 802.11 teal, LLC/SNAP muted, IPv4 blue-light, ICMP green, payload white, FCS grey, corrupted orange), hover or tap a byte for its field readout, and at the end of every attempt runs a real CRC-32 over the received bytes against the received FCS: that comparison, not the corrupted-symbol count, decides ACK vs retransmit. Emit interval is 7 s divided by the symbol count, clamped 30 to 60 ms, so a frame takes about 7 s at 1x regardless of MCS. To change the demo frame, edit and rerun `make-pcap.py`, then rebuild; keep the payload printable ASCII so the ASCII column reads. Canvas animation: a Yagi on the left (mast, boom, reflector, glowing folded-dipole driven element, four directors) aimed along a drawn main lobe at a front-on constellation on the right; ambient blue specks ride the lobe; each data symbol is a bright particle with a tail that rides the cone as a helix (`pathAt`: base point linear along the axis from the driven element to the constellation centre; radius = symbol amplitude x `coneW(s)`, the lobe half-width, which grows from 5px to R so the orbit widens with the beam; angle = s x TURNS x 2pi + the symbol's phase, so at s=1 the helix seen end-on is exactly the constellation point; a slight x shear of 0.22 gives the loops a 3D slant and ramps to 1 over the last 28 percent so the final turn becomes the circle drawn on the grid face). The receiver is drawn twice: `drawPlane` is the constellation seen nearly edge-on in the side view (a thin plane at `L.cx`, width `L.pw` = 2R x `SH` 0.16, Q up, I as depth; the helix's constant x-shear is the same `SH`, so a symbol lands exactly on its projected point), and `drawInset` is the face-on constellation in a square inset (`L.fx, L.fy, L.Rf, L.IS`; right of the canvas on desktop, stacked below the side view on phones, where the canvas grows to about 530px). `target()` is always face-on geometry and `toSide()` projects it; `land()` decodes whichever cell the point fell in (outer cells extend to the edge) and rebuilds the received bits with an inverse Gray code, so a corrupted symbol's bits are the cell it actually hit, not a random flip. Hits are clickable in either view (`nearDot`, 10px): a `.qam-hit` readout under the hex pane names the symbol, bits, byte(s) and field, offset from the cell centre and the decode, and the byte cells get `.sel`. The scatter is physical: `lb` holds a link budget (20 dBm, 10 dBi Yagi, 2 dBi client, 7 dB NF, free space for the first metre then exponent 3 or free space on the `qam-model` chip, distance 3 to 60 m on the `qam-dist` slider, default 30 m, up to three draggable walls at `WALLS` dry 3 / cinder 6 / brick 12 dB, tap the x above a wall to remove it); `snrDb()` = received power minus the thermal floor for the current width, `sigmaPx()` turns it into a per-axis Gaussian in constellation units (Es from the level set), interference still adds `noise x Rf x 0.16`; `SNRMIN_HT` / `SNRMIN_AG` are typical minimum-SNR tables used for the readout only, rate adaptation reacts to the real corruptions. The Link budget chip shows the profile strip (`drawProfile`: dBm against distance, wall steps, noise floor, SNR bracket, which MCS holds) and the `qam-lbrow` controls; walls stay in the scene when it is hidden and dim the lobe by their loss. The Hits chip cycles the face-on target through hits, heat map and both: `hc` is an offscreen copy of the inset that accumulates every landing with 'lighter' and decays with 'destination-out' (cheap circles, throttled to one frame per 20 us of channel time at the frame scale); `evmDb()` is the RMS error vector over the last 300 landings; `heatClear()` wipes both whenever the picture they measured changes (heat chip, MCS, standard, streams, width, multipath, band). Multipath is one specular bounce (`bounce()`, midpoint of the wall segment by the image-source method); each symbol is one subcarrier (`subOf`, a prime stride across NSD) and its fade is `gainAt(dM, fr)`: extra path in metres from the bench scale, times that subcarrier's frequency, plus a pi phase flip at the reflection, magnitude 0.6. The echo is a real particle in `fly` (`f.ech`, `f.par`) that rides the reflected polyline with the helix phase flipping at the bounce and arrives later by Le/Ld; the direct particle waits at s=1 until its echo lands, then `land()` runs with the equalised SNR (plus 20log10 g), records the vector sum `vs` drawn in the inset (direct + echo = resultant, upfade/downfade) and `drawResp` plots |H(f)| across the width with a dot per particle in flight (desktop only). Streams: `txOff(st)` stacks extra driven elements on the mast (TX2 up, TX3 down), RX1..RXn sit beside the plane, `emit(L,st)` launches one particle per stream per slot on the same subcarrier in `STC` colours, and `land()` charges 6 dB per stream beyond the channel rank (1 in line of sight, 2 with the reflector), a model, not a matrix solve. Landed dots are stored per cell with a fractional offset and re-projected every frame, and in-flight symbols re-aim on resize, so a window resize or fullscreen toggle mid-frame never strands dots in the beam. Interference is a chip, off by default (`intOn`); with it on, hover or touch on the canvas is interference (orange blob, 48px): particles passing through pick up noise, land in the wrong cell (orange dot), the frame fails, no ACK, ACK timeout, DIFS plus binary-exponential backoff, retry; after two failed attempts the MCS steps down (rate adaptation), after three clean frames it steps back toward the selected MCS; seven attempts drops the frame. Timings: 40 us preamble, 13.6 us OFDM symbol, SIFS 16, slot 9, DIFS 34, ACK 44, ACK timeout 50, CW 15 to 1023. Antenna menu (`ANT` table: omni, down-tilt omni, patch, sector, narrow panel, Yagi; each with gain, half-power beamwidth, front-to-back, a lobe width factor `kw`, a glyph and a `pat(theta)` in the plane of the screen, which is the elevation plane; `patA(th)` applies the aim and feeds the lobe, the dashed pattern, the field map, the photon spray and `rxFracCalc`; `gtx()` is the gain toward the client, `ANT.g + 10log10(patA(0))`, and replaces the old fixed GT in `prx`/`prxAt`). Drag on the antenna (56px, 34 on phones) rotates `aim`, tap without moving resets it; drag on the RX plane moves the client along the bench: `cliT` in layout() places `L.cx` between 40 and 100 percent of the way to `L.cxB`, `setDist()` maps 3 to 60 m log-wise and syncs the distance slider. The profile strip has a fixed 0 to 60 m axis with the client as a dot, and on desktop a small polar plot of the pattern with the client direction marked and the off-peak dB. Room chip (`room`, `ROOM` losses ceiling 6 / floor 7 / wall behind 4 dB, `roomGeom`, `roomPaths` ranks direct and one-bounce paths by net gain = pattern gain toward the surface + antenna gain − reflection − extra path loss, `linkGain()` feeds `gtx()`, `drawRoom`, and `emit` sets `f.via` so `pathAt` routes the particle antenna → surface → plane with a phase flip and a frame blend over the last 20 percent so it still lands on its constellation point). Scene menu (`scene` bench | link): Long link is a separate block (`LL` state, `llModel` with F1 = sqrt(λ d1 d2 / d), earth bulge d1 d2 / 2kR with k = 4/3, knife-edge loss `keLoss(v)`, worst of the obstacles and 39 ground samples, budget PTX + 2·gain − FSPL − diffraction against the same noise floor; `drawLink` with scenery by distance tier, an earth fill that swallows a blocked line, draggable tree/building/hill via `llPointer`, readout with verdict and the vertical exaggeration; `#qam-llrow` has the log distance slider 30 m to 50 km and both mast heights; `stepInner` diverts to `drawLink` and `setCur` to `llPointer` when the scene is link). Controls: Standard (802.11a/g, n, ac, ax, be; the `STD` table sets symbol time 4 or 13.6 us, data subcarriers per width, allowed widths, MCS list, max streams, preamble by stream count, carrier 5.2 GHz; a/g uses its own eight-rate table and the ladder reads RATE), MCS, streams, width, a Time slider (0 to 4, four bands: 0 to 1 frames, real time to 1 ms per screen second, no flight, a DCF cycle stepped in real microseconds with a to-scale strip of the last 1.2 ms and a frames-per-second estimate, symbols land instantly, the cursor in the cone corrupts a share of them; 1 to 2 symbols, today's particle view, 8x down to 0.125x with the label computed from the real airtime; 2 to 3 waves, 1e8.3 to 1e9.3 slow-motion, the symbol scene freezes and a low-resolution field of the carrier renders through an ImageData map shaped by a textbook Yagi amplitude pattern, cos^5 main lobe, side lobes near 65 degrees, back lobe, with 1/r^0.4 falloff, a mirror-image source below the wall when Multipath is on, and the cursor as a second radio on a channel 10 percent higher; 3 to 4 photons, 1e9.3 to 1e10.3, photons sampled from the power pattern travel at c on a 3 m bench with a running count against the real 3.9 x 10^17 per symbol and the share of the pattern inside the receiver's aperture), pause, Multipath toggle (reflector under the beam; each symbol gets a teal echo on a longer path; fade gain |1 + 0.6 e^(i phi)| from the extra path length at a 34px wavelength; the receiver equalises amplitude so the fade scales landing noise by 1/gain; Streams >= 2 models two RX chains and combines the power of both fades), Compare rates table (rows clickable), click on text for the explainer. Every attempt opens with a preamble (eight white pulses, constellation rotated by a random carrier offset that eases to zero, LOCKED label) before data; symbols corkscrew down the beam as phasors (radius = amplitude, start angle = phase, TURNS=5), trails persist full length and fade from the source once the particle passes 90 percent, then ghost out after landing; "Follow a symbol" tags the next symbol, slows to 0.5x, draws a 3x lens with a phasor mini-plot and a caption (bits, amplitude, phase, then the receiver's verdict), and restores speed. A live MCS ladder sits top-left: bright step = rate in use, outlined = selected, marker eases between steps, flash on rate up/down, eased Mb/s figure. Interference radius 48px (36 on mobile). Rendering has four detail tiers keyed to speed (slower = more detail: trail point spacing 2.2 to 9px, trail cap 260 to 50 points, specks 150 to 40, blur only at the top tiers) plus a governor that drops a tier when the measured draw cost passes 9 ms and recovers below 3.5 ms; trails are stroked one path per half-turn of the corkscrew, landed dots and constellation points are batched paths with no shadows. `root._dbg()` returns drawMs, tier, counts. Fullscreen is a pseudo-fullscreen (fixed, opaque, canvas 56vh, touch-action none so a finger drags interference instead of scrolling; Escape exits); on touch devices the hint says to use it. Pauses when hidden, static under reduced motion. Kit colours only; orange is the interference and warning colour.

## Deploy gotchas

- `git pull --rebase` before pushing. GitHub commits to `CNAME` itself when the custom domain changes in repo settings, so the remote can be ahead with nobody having pushed.
- DNS is Cloudflare, CNAME `@` and `www` to `loopdetectedlolz.github.io`, proxy OFF. The grey cloud is required; proxying breaks certificate issuance.
- Old `#/post/<slug>` links redirect to `p/<slug>.html`. Keep that redirect in `theme/app.js`.
- A dense figure in a post goes in `<figure class="wide"><div class="pan">`: the pan scrolls sideways on a phone so the figure stays legible instead of shrinking to nothing, and the caption stays put outside it. Same idea as the tables.
- `.band` is the call-to-action card. The 5 GHz spectrum strip in the channel 173 post is `.spectrum`: it used to be `.band` too, and its `height:64px;overflow:hidden` silently clipped every CTA card on the site, including the one under the simulator, until 2026-09-11. Two components, two names.
- Category deep links are `index.html#cat=NAC`. The nav pills use them, and `app.js` listens for `hashchange`, so a filter change from any page works without a reload.
- `build-blog.py` still finishes the HTML when `rsvg-convert` is missing; it warns and keeps the existing `og/*.png`. Run it on the Mac (Homebrew librsvg) to refresh OG cards.
- Run a new post through `linkedin.com/post-inspector` before sharing it. LinkedIn caches the first scrape for weeks.

## Working on the simulator without touching the site

`python3 lab.py` builds `lab.html` from `theme/widgets/qam-lab.html`, serves it on 127.0.0.1:8823 and reloads the browser every time that widget, `theme/style.css` or `theme/app.js` is saved. The page carries an orange LAB bar saying how far the lab widget has drifted from the live one, and a button that opens phone and tablet frames of the same widget (loaded on demand, because each frame runs its own copy of the animation).

The live widget, `theme/widgets/qam.html`, is only written by `python3 lab.py --promote`, which copies the lab widget over it and rebuilds the site; until then the published simulator keeps serving whatever was last pushed. `--diff` shows what the lab has that the live one does not, `--reset` throws the lab copy away and starts again from live, `--build` renders `lab.html` once without serving. `lab.html` is generated and git-ignored; `qam-lab.html` is tracked so work in progress has a history and survives a `git clean`.

## The simulator core

`theme/sim/` is the second generation of the simulator, split so the physics can be tested without a browser. `core.js` is the namespace, a seeded RNG (mulberry32, so a screenshot and a test are reproducible) and `NFN.State`, which carries a tool's whole configuration in the URL hash as `#capacity/v1?bw=80&g=60,ax2,video;90,ac1,web`: a link is the argument. `rf.js` is propagation (free space, log distance, wall losses, noise floor, Fresnel, earth bulge, knife edge, antenna patterns from a half-power beamwidth, cell radius). `phy.js` computes rates from the constellation, coding rate and subcarrier count rather than looking them up, so matching the standard's table is a result: 2 streams of MCS 11 on 160 MHz comes out at 2402 Mb/s. `mac.js` is the tax: backoff, DIFS, SIFS, block ack, the cost of a retry, beacon overhead. `capacity.js` turns a client mix into airtime and airtime into access points, and reports which ceiling binds, the airtime or the client count per radio, because airtime alone will happily tell you three radios for three hundred clients.

`node simtest.js` asserts all of it against figures that can be checked independently: free space at 1 m and 5.2 GHz is 46.76 dB, 1500 bytes at 6 Mb/s is 2072 us on air, F1 at the middle of a 10 km link is 12.0 m, the earth bulge at the middle of 50 km is 36.8 m, and the PHY rates match the tables in 802.11n, ac, ax and be. Run it before promoting anything out of the lab.

The first tool built on it is the capacity planner, `theme/widgets/tools-lab.html`, worked on with `python3 lab.py tools`. It is lab-only: nothing in `build-blog.py` includes it, so it is not on the site until it is wired into a page. In the lab the model files load as separate scripts for a fast reload; the real build will concatenate them into the page.

`python3 capture.py` regenerates the figures the posts take from the simulator, so a tool change is a re-run rather than a fresh round of screenshotting. Each shot drives `simulator.html` in a headless browser, entirely by script rather than by clicking, because a click scrolls the control into view and a recording then starts somewhere down the page. `academy-01` writes `media/academy-01-six-db.png` (four link budget strips at the lesson's own lab distances, 2, 4, 8 and 16 m, free space, omni, captured at devicePixelRatio 2 and shown at half size) and `media/academy-01-six-db.mp4` plus its poster. The step between the strips is read back from `root._dbg().lb`, which reports the widget's own distance, received power, SNR, gain toward the client and noise floor, and the crop comes from `root._dbg().strip`, the panel rectangle in canvas units: neither number is worked out a second time in the capture script, so the figure cannot drift from the tool. Add a shot by adding a function to `SHOTS`.

`python3 regress.py` is the visual regression harness: every page at 360, 768 and 1280, asserting no horizontal scroll, no page errors, no broken images, the mascot fixed at z-index 60, at least 140 px of clearance at the end of the content (page padding plus main padding, since the padding moved to `main` when the footer was pinned to the bottom), at most one green call to action per view, no contact copy outside the socials page, and no tap target under 38 px.
